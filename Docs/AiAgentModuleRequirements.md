# 可选 AI Agent 模块需求

## 1. 文档状态

- 状态：需求基线已实现；外部内部模型实网验收待提供连接条件
- 日期：2026-10-08
- 范围：DiaryApp 内置 AI Agent、模型连接、网络代理、工具和数据边界
- 不包含：具体项目拆分、类设计、数据库 schema、UI 视觉稿和实施排期

详细实现方案和评审结论见 [`AiAgentModuleDesign.md`](AiAgentModuleDesign.md) 与
[`AiAgentModuleDesignReview.md`](AiAgentModuleDesignReview.md)。

本文基线已经由 `Diary.ModuleBase`、`Diary.ModuleUI`、`Diary.Agent` 和 `Diary.Agent.UI` 实现。模块随主程序发布、默认禁用，并保持现有 AI 脚本上下文、授权快照和只读 `Diary.Mcp` 的独立边界，详见
[`AiScriptContextDesign.md`](AiScriptContextDesign.md) 与 [`AiAgentUserGuide.md`](AiAgentUserGuide.md)。

## 2. 目标

为 DiaryApp 增加一个可选的内置 AI Agent，使用户能够通过自然语言查询、汇总和辅助处理日记事项，同时满足：

1. AI 不是 DiaryApp 的必需功能；
2. 支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 三种协议格式，并接入公司内部部署的 DeepSeek、GLM 等兼容模型；
3. 模型只能通过已注册工具访问 DiaryApp 数据，工作项的本地备注不向模型提供；
4. 写入、脚本执行和 Tracker 提交等副作用必须由应用校验并由用户确认；
5. 模型 API Key、代理密码和认证 Header 使用现有加密配置或环境变量保存，并且不写入日志；
6. 内置 Agent 与外部 MCP 可以独立启用和使用；
7. 内置 Agent 可以通过注册工具搜索和读取网页，但不得获得任意协议、任意方法或本地文件访问能力。

## 3. 非目标

第一阶段不要求：

- 多 Agent 协作；
- 模型直接访问数据库、任意 SQL 或任意本地文件；
- 模型直接执行 Shell、安装依赖或调用未注册服务；
- 向模型开放任意 HTTP 方法、任意目标地址或不受限制的浏览器控制；
- 厂商专用 SDK 和厂商专属 Agent 平台；
- OpenAI Assistants、Anthropic Managed Agents 或厂商托管 Agent 平台；
- Responses WebSocket、Conversations、Background Mode 和服务端托管会话；
- OpenAI/Anthropic 内置网页搜索、文件搜索、代码执行和计算机控制工具；
- 自动按价格、速度或负载选择模型；
- 多连接自动故障转移；
- 运行时热卸载模块；
- PAC、多级代理、动态代理脚本或跳过 TLS 验证；
- 无确认删除事项、执行脚本或提交 Tracker 工时。

## 4. 核心决策

### 4.1 AI 是可选模块

AI 实现不得成为 `Diary.App` 核心功能的必需依赖。目标状态如下：

| 模块状态 | 预期行为 |
| --- | --- |
| 未安装 | 不加载 AI 程序集，不显示 AI 页面，不要求模型配置，不产生模型请求 |
| 已安装但禁用 | 仅在模块管理中可见，不创建模型客户端，不读取日记数据 |
| 已启用但未配置 | 显示 AI 页面并引导添加模型连接，不发起后台探测 |
| 已配置但测试失败 | 保留配置和诊断结果，不允许设为可用 Agent 连接 |
| 仅支持普通对话 | 允许对话，不注册 DiaryApp 工具 |
| 支持工具调用 | 允许进入仅包含已启用工具的 Agent 模式 |

模块安装、启用、禁用和卸载在第一阶段可以要求重启应用。模块加载失败不得阻止 DiaryApp 核心功能启动。

### 4.2 连接显式选择协议格式

第一阶段支持三种协议格式：

| 协议 | 默认路径 | P0 最小范围 |
| --- | --- | --- |
| OpenAI Chat Completions | `/chat/completions` | messages、流式响应、Function Calling、tool result |
| OpenAI Responses | `/responses` | input/output Items、typed SSE、自定义 Function Calling、function call output |
| Anthropic Messages | `/messages` | content blocks、流式事件、tool use、tool result |

协议由连接显式配置，不根据模型名称、Base URL 或错误响应自动猜测和切换。同一个模型服务如果暴露多套协议，可以创建多个独立连接分别探测。

三种协议共享 DiaryApp 内部的消息、工具和流式事件模型，各协议适配器只负责：

- 请求序列化和认证 Header；
- 非流式响应解析；
- SSE 事件与工具参数增量拼接；
- 工具调用和工具结果的协议映射；
- stop/finish reason、usage 和错误归一化。

Responses P0 默认使用 `store=false` 并由 DiaryApp 在当前会话内维护输入和输出 Items，不依赖 `previous_response_id` 或 Conversations。适配器必须保留完成工具闭环所需的输出 Item 和 `call_id`，但不实现 OpenAI 托管工具。

不得把“可以普通聊天”等同于“可以运行 Agent”。模型连接只有通过工具调用闭环探测后，才可以注册 DiaryApp 工具。

### 4.3 DeepSeek 和 GLM 是连接，不是协议

DeepSeek、GLM 和其他服务不作为不同 DiaryApp 插件或厂商代码分支实现，而是选择某个协议适配器的独立连接配置，例如：

```text
内部 DeepSeek - Chat Completions
内部 GLM - Responses
内部模型网关 - Anthropic Messages
本地兼容服务 - Chat Completions
```

默认连接根据内部实际服务的工具调用稳定性确定，不根据模型品牌硬编码。用户可以保留多个连接、设置全局默认连接，并在新会话开始前选择其他连接。

## 5. 模型连接管理

### 5.1 基本操作

用户应能够：

- 添加、编辑、复制和删除连接；
- 启用或禁用连接；
- 测试连接；
- 设置全局默认连接；
- 在新会话中选择连接；
- 查看最近一次探测时间、能力和失败原因。

修改全局默认连接只影响新会话。已开始的会话保持原连接；如果用户主动切换，应创建新的模型上下文，不复用旧连接的服务端会话标识或厂商私有状态。

### 5.2 配置字段

第一阶段至少支持：

| 字段 | 说明 |
| --- | --- |
| 连接 ID | 稳定、唯一，不因显示名称修改而变化 |
| 显示名称 | 例如“内部 GLM” |
| 协议格式 | OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages |
| Base URL | 例如内部网关的 `/v1` 根地址 |
| 请求路径 | 使用协议默认路径，允许连接级覆盖 |
| 模型名称 | 使用内部服务实际接受的模型名 |
| 上下文窗口 | 当前模型支持的总 Token 数，例如内部 1M 模型填写 `1000000` |
| 自动压缩 | 是否在达到连接级阈值时压缩较早会话 |
| 压缩阈值 | 上下文窗口使用率，允许 50%～95%，默认 75% |
| 认证方式 | 无认证、Bearer Token、自定义 Header |
| API Credential Reference | 指向凭据存储，不在连接 JSON 保存正文 |
| 请求超时 | 模型请求总超时 |
| 连接超时 | DNS、代理和 TCP/TLS 建连超时 |
| 额外 Header | 普通值可直接保存，认证值使用 Credential Reference |
| 代理配置 | 继承、系统、直连或自定义 |
| 兼容选项 | 只保留经过实际需求验证的少量覆盖项 |

不得依赖远程模型列表接口。UI 应同时支持“刷新模型列表（若可用）”和手动填写模型名称。

## 6. 代理服务器

### 6.1 代理层级

代理属于 AI 模型连接的网络配置，不修改 DiaryApp 全局代理。支持两级设置：

1. AI 模块默认网络设置；
2. 单个模型连接继承或覆盖默认设置。

代理配置不得影响应用更新、Jira、Redmine、MCP 或其他插件的网络请求。

### 6.2 代理模式

| 模式 | 行为 |
| --- | --- |
| 继承 | 使用 AI 模块默认网络设置 |
| 跟随系统 | 使用操作系统或代理环境变量 |
| 直连 | 明确绕过所有代理 |
| 自定义 | 当前连接使用指定 HTTP 代理 |

第一阶段自定义代理支持：

- HTTP 代理；
- HTTPS 请求通过 HTTP CONNECT；
- 可选用户名和密码；
- 绕过本地地址；
- 精确主机名和域后缀绕过列表；
- 独立连接测试。

代理密码不得嵌入代理 URL。配置只保存用户名和密码引用，密码正文进入凭据存储。

### 6.3 客户端隔离

不同代理或直连策略必须使用相互隔离的 HTTP handler/连接池。模型请求不得每次新建和立即释放 `HttpClient`；连接配置变化后应创建新客户端，并在旧请求结束后释放旧客户端。

## 7. 能力探测

连接测试不是单次 HTTP 200 检查，应分层验证。

### 7.1 基础连接

验证：

- Base URL 和路径有效；
- DNS、代理、TCP 和 TLS 可用；
- 认证信息有效；
- 模型存在且可调用；
- 非流式普通对话可完成。

### 7.2 流式响应

验证：

- `stream=true` 是否可用；
- SSE 分片是否可解析；
- 文本增量是否能正确拼接；
- 代理是否缓冲或中断长连接；
- 流式工具名称和参数是否能正确拼接。

流式失败但非流式成功时，连接可以降级使用非流式模式。

### 7.3 工具调用闭环

使用无副作用探测工具验证：

1. 模型返回对应协议的合法工具调用；
2. 工具名、调用 ID 和参数可解析；
3. 参数是合法 JSON；
4. 服务接受对应协议的工具结果消息或 Item；
5. 模型能在收到工具结果后产生最终回答；
6. 连续两轮工具调用不会破坏消息历史；
7. 无效参数返回后模型能够修正或安全终止。

能力结果至少记录普通对话、流式、工具调用、流式工具调用、并行工具调用、强制工具选择及测试时间。历史探测结果只用于提示和预配置，实际运行仍必须处理服务能力变化。

## 8. Agent 工具和执行策略

### 8.1 工具分级

工具分为三个等级：

| 等级 | 行为 | 示例 |
| --- | --- | --- |
| 只读 | 工具启用后可以自动调用 | 标签、模板、事项查询/详情、统计分析、导出格式与模板目录 |
| 草稿 | 自动生成结构化建议，但不落库 | 事项草稿、日报、周报、脚本草稿 |
| 写入 | 展示参数或变更预览并等待用户逐次确认 | 创建/更新事项、从模板创建事项、导出日报/周报、写入剪贴板、发送应用通知 |

第一阶段优先实现只读工具；草稿和确认后写入按实施阶段逐步开放。

内置 Agent 不提供页面跳转、日期切换、事项选择或筛选条件修改等 UI 操作工具。删除事项、模板、标签或远程数据的能力不向 Agent 开放；外部 MCP 工具声明的删除操作同样由本地策略禁用，不能仅依赖逐次确认放行。MCP 本地策略保存时拒绝启用名称中带有删除语义的工具，工具列表刷新注册时再次过滤，避免旧配置或错误风险分级绕过限制。

### 8.2 工具来源

内置 Agent 不直接调用任意 `DbInterfaceBase` 方法。应优先复用或适配现有稳定能力：

- `IWorkItemQueryScriptApi`；
- `ILogItemScriptApi`；
- `ITemplateLogItemScriptApi`；
- `ITemplateScriptApi`；
- `IHostCapabilitiesScriptApi`；
- `IClipboardScriptApi`；
- `IUserInteractionScriptApi`；
- 现有预览、执行策略、结构化错误和幂等能力。

工具注册表只向模型暴露当前连接支持且用户已经启用的工具。未启用工具不得仅依赖 Prompt 禁止，而应从请求中的工具列表移除。

### 8.3 参数和副作用校验

所有工具调用必须经过：

```text
JSON 解析
  -> JSON Schema 校验
  -> 字段长度、日期和数值范围校验
  -> 工具启用和写入策略校验
  -> 业务规则和并发状态校验
  -> 必要时展示确认
  -> 执行并记录结果
```

不得依赖模型服务的 `strict` 参数代替应用侧校验。写入工具必须支持幂等键，防止网络重试、模型重复调用或用户重复确认造成重复副作用。

## 9. 工作数据边界

### 9.1 最小上下文

每次模型请求只发送完成当前任务所需的内容：

- 固定 Agent 指令；
- 当前页面、当前日期和必要的当前选择；
- 受预算限制的最近会话消息；
- 当前获准工具的定义。

历史工作项和附加字段通过工具按需查询，不把整个数据库或完整快照加入 Prompt。

### 9.2 本地备注

工作项的本地备注对应数据库的 `WorkGetNote`/`GetWorkNotesByWorkItemIds` 数据。内置 Agent 的查询接口和工具 DTO 不包含该字段，也不调用本地备注读取接口。

标题、日期、时长、标签、模板、附加字段和 Tracker 状态等普通工作数据可以直接用于 Agent 查询和汇总。若未来确实需要向 AI 提供本地备注，应作为单独功能重新评审，不能通过通用字段或原始数据库查询绕过这一边界。

### 9.3 内容处理

工作项标题、附加字段、模板、网页内容和模型输出都作为数据处理，不允许覆盖 Agent 的固定指令或直接获得额外工具权限。工具结果优先使用结构化 DTO，避免把数据文本拼接成系统指令。

## 10. 凭据保存

需要保护的凭据包括：

- 模型 API Key；
- 自定义认证 Token；
- 代理密码；
- 认证 Header；
- 网页工具认证 Header。

P0 复用 DiaryApp 现有认证加密能力保存这些值，同时支持环境变量引用和仅当前会话保存在内存。配置模型只保存凭据引用，不在连接 JSON 中重复保存正文。

最低要求：

- UI 不回显已经保存的完整凭据；
- 日志、诊断导出、AI 上下文快照和模型消息不得包含凭据；
- 删除连接时允许同时删除对应凭据；
- 后续如有企业合规需要，再扩展 Windows Credential Manager、DPAPI vault 或 Linux Secret Service，不作为 P0 前置条件。

## 11. 会话和运行循环

### 11.1 Agent 循环

```text
用户输入
  -> 模型响应
  -> 文本或工具调用
  -> 工具校验与执行/确认
  -> 工具结果返回模型
  -> 最终回答或下一轮工具调用
```

运行时应限制：

- 最大 Agent 轮次；
- 最大工具调用次数；
- 最大单次工具结果大小；
- 最大上下文预算；
- 请求超时；
- 最大输出 Token；
- 连续失败次数。

建议初始默认值为最大 8 轮、最多 12 次工具调用、单次事项最多 100 条。达到限制后必须安全终止并说明原因。

### 11.2 会话记录

可以保存：

- 用户消息和最终回答；
- 工具名、参数摘要、结果状态和错误类型；
- 用户确认或拒绝；
- 使用的连接 ID 和模型名；
- Token 用量和耗时。

### 11.3 自动上下文压缩

每次 run 前必须估算固定指令、历史摘要、消息、Responses 协议状态、工具 schema 和预留输出所占 Token。估算值达到连接配置的阈值时自动压缩较早的完整对话轮次，同时满足：

- 保留最近两轮完整用户/助手/工具链，不拆分 assistant tool call 与对应 tool result；
- 较早轮次由同一连接生成结构化摘要，摘要请求不携带工具；
- 摘要作为不可信历史数据注入固定指令，不能授予工具权限或覆盖安全规则；
- 摘要调用失败时使用有长度上限的本地确定性摘要，不能因此阻断主请求；
- 压缩后清理与旧消息绑定的协议状态，尤其是 OpenAI Responses output items；
- 会话文件保存摘要、压缩次数和压缩后保留的用户消息/最终回答，不重新保存已经被摘要替代的完整历史；
- 工作项本地备注仍不得进入摘要输入、摘要正文或持久化文件。

不得保存 API Key、代理密码、Authorization Header、模型隐藏推理或工作项本地备注。

## 12. UI 要求

### 12.1 AI 页面

至少提供：

- 会话消息列表；
- 输入、发送和停止生成；
- 当前连接和运行模式；
- 流式文本；
- 工具调用状态和可折叠详情；
- 写操作确认卡片；
- 错误、重试、新建会话和删除会话；
- 已启用工具和“本地备注不提供给 AI”的状态说明。

模型连接不支持工具调用时，页面必须显示“普通对话模式”，并禁止查询或修改 DiaryApp 数据。

### 12.2 连接设置

设置页至少提供：

- 模型连接列表和状态；
- 添加、编辑、测试、设为默认和删除；
- Base URL、路径、模型和认证；
- 代理模式、地址、认证和绕过列表；
- 最近探测能力和错误；
- API Key、代理密码是否已保存的状态，不回显正文。

### 12.3 写操作确认

确认卡片必须展示实际变更字段，例如日期、标题、工时、标签和备注，提供“确认”“编辑后确认”“拒绝”。删除、批量修改、脚本执行和 Tracker 提交始终要求确认，第一阶段不提供永久跳过确认选项。

## 13. 外部数据与工具

### 13.1 目标和边界

内置 Agent 应通过统一工具注册表使用 DiaryApp 内置工具和外部数据工具。模型本身不得获得原始 `HttpClient`、任意 URL 请求、Shell 或浏览器控制能力。

目标结构：

```text
AgentToolRegistry
  |- DiaryApp 内置工具
  |- web_search
  |- web_fetch
  `- 可选 MCP/专用连接器工具
```

普通公开网页优先使用受控 `web_search`/`web_fetch`；公司知识库、GitLab 或其他结构化内部系统优先使用 MCP 或专用连接器。现有 `Diary.Mcp` 继续作为向外部 Agent 提供 DiaryApp 授权快照的 MCP Server，不负责内置 Agent 的网页访问。

### 13.2 `web_search`

`web_search` 用于搜索外部信息，至少接受查询文本和最大结果数，返回标题、URL 和摘要。搜索实现通过可替换 Provider 接入公司内部搜索服务、自建搜索网关或第三方搜索 API，不把特定搜索供应商写死在 Agent 循环中。

搜索请求遵守以下边界：

- 搜索词可以来自用户输入、工作项标题、附加字段或 Tracker 内容；
- 工作项本地备注不会进入 Agent 上下文，因此不能用于生成搜索词；
- API Key、Token、连接字符串和代理凭据不得进入搜索词；
- 结果必须携带来源 URL、标题、摘要和提供方标识。

### 13.3 `web_fetch`

`web_fetch` 用于获取指定 URL 的正文，第一阶段仅允许 `GET`/`HEAD`，不提供任意方法、请求正文或模型自定义认证 Header。结果至少包含：

- 请求 URL 和最终 URL；
- 页面标题；
- Content-Type；
- 提取后的正文；
- 获取时间；
- 是否截断；
- 来源和外部内容标记。

HTML 处理应移除脚本、样式、表单和不可见内容，按正文大小、解压后大小、字符数、重定向次数和总耗时设置预算。第一阶段处理静态 HTML、纯文本和受限 JSON；PDF、图片、音频和 JavaScript 动态页面后续评估。

### 13.4 公网和内部站点策略

网页访问支持两种目标范围：

| 策略 | 行为 |
| --- | --- |
| 公网 | 仅访问允许的 HTTP/HTTPS 公网目标，拒绝本机、链路本地、私有地址和云元数据地址 |
| 内部站点 | 访问用户显式配置的内部主机或域名 |

只允许 HTTP/HTTPS，拒绝 `file:`、`data:`、`ftp:`、`gopher:` 等协议。公网模式下拒绝 localhost、链路本地、私有地址和常见云元数据地址，并在重定向后重新检查目标。内部站点由用户在设置中显式加入，不引入管理员策略中心。

连接级认证只发送给配置的目标主机；跨主机重定向移除认证信息。这里的限制用于避免误访问本机服务和凭据误转发，不构建企业级网络出口治理体系。

### 13.5 认证和代理

外部数据连接可以配置无认证、Bearer Token、Basic 认证或自定义 Header。认证值通过第 10 节的凭据存储保存，不自动导入浏览器 Cookie，也不复用模型 API Key。

网页和搜索工具使用独立网络配置，可选择系统代理、直连或自定义代理，并与模型连接和远程 MCP 的 HTTP 客户端/连接池隔离。例如内部模型可以使用 AI 代理，公开网页使用系统代理，公司 Wiki 使用内网直连。

### 13.6 工具启用和内容处理

网页正文、搜索摘要、MCP 结果和专用连接器结果作为工具数据返回，并携带来源和获取时间。页面中的“忽略指令”“调用工具”等文字不得被提升为系统指令。

外部工具在设置中按工具或 Provider 启用：

- 允许搜索公开网页；
- 允许读取公开 URL；
- 允许访问配置的内部站点；
- 启用或禁用每个 MCP/连接器。

启用的只读外部工具可以直接执行；会写入远程系统或影响 DiaryApp 数据的工具仍需确认。服务器提供的只读、破坏性、幂等等声明只作为提示，最终是否确认由 DiaryApp 的工具定义决定。

### 13.7 MCP 和浏览器扩展

MCP Client 是外部工具的可选扩展方式，不是普通网页获取的必需条件。第一阶段可以只预留工具来源和策略；后续按需求支持本地 stdio 或远程 Streamable HTTP MCP Server，并优先限定为工具发现和工具调用。

JavaScript 动态网页、浏览器登录态、点击、表单提交、文件上传下载等能力应通过独立浏览器工具或 MCP 实现，并作为更高风险能力单独授权。第一阶段不实现浏览器自动化，也不允许网页自动触发 DiaryApp 写操作。

### 13.8 验收要求

外部数据工具完成时至少满足：

1. `web_fetch` 能读取允许的静态网页并返回带来源和截断状态的正文；
2. 公网模式下的本机、私有地址、非 HTTP(S) 协议和越权重定向被拒绝；
3. 内部站点只能通过显式配置访问；
4. 认证 Header 不会发送到重定向后的其他主机；
5. 网页中的指令文本不能提升工具权限；
6. 下载大小、正文长度、重定向、超时和并发均受预算限制；
7. 日志和诊断导出不包含页面认证信息；
8. 未启用外部数据工具时，模型请求中不出现对应工具定义。

## 14. 内置 Agent 与 MCP

两者是独立能力：

| 内置 Agent | MCP | 行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 无 AI 能力 |
| 关闭 | 开启 | 仅由外部 Agent 使用授权快照 |
| 开启 | 关闭 | 仅使用 App 内置 Agent |
| 开启 | 开启 | 两种入口同时可用，工具配置和运行记录独立 |

`Diary.Mcp` 不需要模型连接，也不得因为内置 Agent 增加写工具。若 AI 最终成为完整可选模块，现有 AI 上下文和 MCP 配置 UI 应评估迁移到该模块，但快照 schema 和只读安全边界保持兼容。

## 15. 日志和错误

日志可以记录连接 ID、模型名、耗时、HTTP 状态、请求 ID、工具名、执行状态、确认结果、Token 用量和降级行为。不得记录凭据、工作项本地备注或模型隐藏推理；完整模型请求/响应只允许在用户显式开启的开发诊断中临时记录，并仍需排除凭据和本地备注。

错误至少区分：

- 模块未启用或没有连接；
- 配置无效；
- DNS、代理、代理认证、TCP、TLS 错误；
- 模型认证失败、模型不存在、限流和服务端错误；
- 请求超时、取消和流中断；
- 不支持工具调用或工具历史不兼容；
- 工具参数无效、工具未启用、用户拒绝；
- 外部 URL 被策略拒绝、重定向越权、响应过大或内容类型不支持；
- 数据库不可用、并发冲突、幂等重复；
- 达到 Agent 轮次或工具次数上限。

错误信息应给出可执行的处理建议，不得回显凭据或工作项本地备注。

## 17. P0 验收标准

P0 完成需同时满足：

1. 删除或不安装 AI 模块后，核心 DiaryApp 能独立启动和使用；
2. AI 模块禁用时不创建模型客户端、不读取日记正文且不产生模型请求；
3. 连接可显式选择 Chat Completions、Responses 或 Anthropic Messages，并分别设置直连或代理；
4. 三种协议适配器均通过模拟服务的普通对话、流式和工具调用闭环测试；内部 DeepSeek 和 GLM 按实际暴露的协议完成真实连接探测；
5. 不支持工具调用的连接只进入普通对话模式；
6. 支持工具调用的连接可完成“用户问题 -> 事项查询 -> 工具结果 -> 最终回答”闭环；
7. 工作项本地备注不会进入 Agent 工具结果或模型请求；
8. 工具参数错误不会绕过应用校验或造成副作用；
9. API Key 和代理密码不出现在连接 JSON、日志、诊断导出和 AI 上下文快照中；
10. 取消、超时、代理失败、认证失败和达到运行上限均能安全结束并给出明确错误；
11. 工具注册表能够区分内置、模块和外部来源，未启用的工具不会进入模型请求；
12. 自动化测试覆盖无模块、禁用、无配置、聊天降级、工具调用、代理、凭据遮罩和本地备注排除场景。

## 18. 实施结论与剩余外部条件

已确定并实现：启动配置启停、会话持久化、三协议、完整分层能力探测、受控网页读取、确认后事项创建、MCP Client、Windows/Linux 发布和模块化 UI。Agent 宿主查询使用不调用备注读取器的无备注模式，并由实际模型请求体唯一标记回归覆盖；`web_search` 仅在宿主提供 `IWebSearchProvider` 时注册，未配置 Provider 时不会向模型公开。

仍需要部署环境提供的验收输入：

1. 内部 DeepSeek、GLM 的真实 Base URL、协议、路径、模型名和凭据；
2. 公司代理认证、企业 CA 或内部 DNS 的实际要求；
3. `web_search` 的具体 Provider；
4. 独立模块在线安装、签名、原子更新，以及 JavaScript 浏览器自动化的后续产品决策。
