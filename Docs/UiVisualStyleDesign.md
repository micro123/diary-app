# UI 视觉样式设计

## 1. 目标

DiaryApp 保留深色工作台和蓝色交互色，通过少量明确的页面模板统一标题、间距、按钮语义和状态表达。
视觉统一不要求所有页面使用相同结构：日记、查询和统计属于工作台；标签、Tracker 实例属于主从管理页；程序设置、模板、数据模板和 Tracker 设置属于模态管理页；Redmine 动态页面属于带页签的管理工作台。

本设计只调整视觉层级和交互语义，不改变数据库、脚本、Tracker 或远程同步行为。

## 2. 页面模板

### 2.1 工作台

适用于日记、工作项查询和统计：

- 日记使用固定宽度日期/事项主栏和可滚动详情栏，日期、事项列表、当天汇总保持独立层级；左侧日期导航固定显示一周，日期右键承载日/周操作，月份标题右键承载月/季度/年度操作，完整月历作为仅用于选择和定位的按需弹层；完整月历每次展开都回到当前选中日期所在的月视图，选择任意日期后立即关闭，相邻月份日期必须精确选中而不能额外翻月；
- 工作项“一般信息”使用稳定标签列和内容列，日期、标题、耗时输入控件共享左边缘，紧凑按钮跟随所属输入控件；
- 查询使用页面标题、已保存查询、条件卡片和结果区，筛选折叠不改变结果可见性；
- 统计在每个统计页签内部使用一致的标题、范围、总计、图表和明细卡片；
- 页面主操作集中在标题或详情头部，危险操作与普通操作分组。

### 2.2 主从管理页

适用于标签、Jira 实例和 Redmine 实例：

- 左侧 `MasterPane` 承载新增、导入导出、列表和删除入口；
- 右侧 `DetailPane` 承载当前对象标题、状态、配置分组和附加规则；
- 列表显示稳定名称和必要的 ID/摘要，不在主栏堆叠完整设置；
- 详情超过可视高度时只滚动详情内容，底部保存/取消保持可达。

### 2.3 模态对话框

适用于程序设置、标签、模板、数据库、脚本运行和 Tracker 设置：

- 普通标题使用白色，不使用红色或绿色表达展开、选中等常规状态；
- 副标题使用较低对比度并允许换行；
- 底部操作区右对齐，顺序为中性操作在前、主操作在后；
- 红色只用于删除、清空数据和明确的不可逆放弃操作。

### 2.4 Tracker 管理工作台

适用于 Tracker 设置、插件状态和 Redmine 动态管理页：

- 保留外层“Tracker 配置 / 插件状态”和内层“Jira / Redmine”页签，维持用户认知和自动化契约；
- 插件状态以状态胶囊、错误卡片和普通/危险操作分组表达；
- Redmine 管理页由实例动态导航和页签共同表达当前位置，不再重复显示外层“Redmine 管理”说明卡；基本信息页签直接展示用户、活动和已导入问题，问题/项目管理保留各自必要的工具栏、分页和表格容器；
- 编辑器内 Tracker 区域使用统一字段标签，并继续服从核心事项只读、已同步锁定和防重复提交边界。

### 2.5 应用状态栏

- 保持 34px 紧凑高度并跟随主内容主题，不使用独立反差底色；状态按钮复用统一悬停反馈。
- 左侧固定放置数据库和 Tracker 健康状态，中部只显示最近一条临时消息，右侧按需显示后台任务、更新状态和紧凑日期。
- 普通状态以短文字、业务图标和 7px 状态点组合表达；蓝、绿、橙、红分别表示信息、成功、警告和错误，不依赖单独的小信息图标触发 Tooltip。
- 临时消息、后台任务和更新状态在无内容时完全隐藏；中部消息限制最大宽度并省略过长内容，完整说明通过整项 Tooltip 获取。
- 后台任务 Flyout 展示任务名称、说明和可用进度；数据库、Tracker、更新和错误消息整项均为可点击入口，命中区域不小于 28px 高。
- 日期采用 `M月d日`，点击继续打开只读日历；用户名、计算机名和源代码入口不再常驻状态栏。

## 3. 基础样式

公共样式位于 `Diary.GUIBase/Resources/AppStyles.axaml`：

| Class | 用途 |
| --- | --- |
| `PageTitle` | 标准页面或设置窗口一级标题 |
| `PageSubtitle` | 一级标题下方的简短说明 |
| `Header` | 需要居中的传统对话框标题，逐步迁移到统一颜色和字号 |
| `DialogFooter` | 右对齐的模态操作区 |
| `EmptyStateTitle` | 完整空状态或错误状态标题 |
| `EmptyStateDescription` | 空状态或错误状态说明 |
| `ToolbarCheckBox` | 工具栏中的 CheckBox 垂直对齐 |
| `PaginationText` | 分页区域文字垂直对齐 |
| `WorkspaceSection` | 工作台中的可展开内容分组 |
| `WorkspaceToolbar` | 工作台中的搜索、筛选和分页工具栏 |
| `PageHeader` | 页面或对话框的标题、说明和主操作容器 |
| `SectionCard` | 具有明确边界的设置、查询、统计或管理区块 |
| `SubtleCard` | 区块内部的次级说明、规则或错误信息 |
| `MasterPane` | 主从管理页左侧列表与新增操作区 |
| `DetailPane` | 主从管理页右侧详情或页面主要内容区 |
| `DetailHeader` | 详情对象名称、说明和状态摘要 |
| `StatusPill` | 保存、同步、插件运行等短状态摘要 |
| `SectionTitle` / `SectionDescription` | 区块标题与低对比度说明 |
| `FieldLabel` | 表单字段标签的统一字重和垂直对齐 |
| `PageActions` / `CompactActions` | 页面级和紧凑操作按钮组 |
| `IconAction` | 复制等仅图标紧凑操作 |

设置项继续复用 `SettingLineBox`、`SettingLineCaption` 和 `SLV`。设置分组展开时只使用蓝色强调，不使用成功色；内容分隔线使用普通边框色，不使用危险色。

页面和区块标题优先使用横向标题行：较大字号的标题在左，精简后的低对比度说明在右，并以底边对齐减少垂直占用。无法在可用宽度内清晰表达的长说明改用信息图标承载完整 Tooltip；不能为了单行布局而挤压主操作或造成说明换行。

事项状态胶囊使用克制的语义色：未保存为琥珀色、待同步为蓝色、已同步为绿色、同步失败为红色、同步结果待确认为橙色；未配置 Tracker 和迁移只读保持中性。组合状态以当前最需要用户处理的状态为准，文字始终保持足够对比度。脚本 API 版本等紧凑身份标识使用带独立填充色和描边的圆角矩形，不能只依靠彩色文字表达，也不能与列表选中背景融为一体。

### 3.1 紧凑密度尺度

- 主窗口与页面根容器合计只保留约 4px 外边距，页面内部的同级主区块间距使用 6～10px，避免容器与页面重复留白；
- `PageHeader` 使用 12px 内边距，`SectionCard` 使用 10px，`SubtleCard` 与 `MasterPane` 使用 8px，`DetailHeader` 使用 12×8px；
- 同级主卡片之间保留 6px，卡片内的小型列表项保留 4px，既保持边界可辨识，也避免出现单卡紧凑但卡片组仍松散的情况；
- 条件显示的卡片使用自身显式外边距，不依赖包含隐藏行的 Grid `RowSpacing`，避免隐藏卡片后相邻区域出现双倍间距；
- 日记页左右主卡片直接使用 4px 间距；两侧均已有完整卡片边框，不再额外绘制中间分隔线；
- 工具栏、页面操作组和对话框底部按钮间距使用 4～6px，可展开分组的标题与内容使用紧凑内边距；
- 紧凑化只减少空白，不缩小正文和字段标签字号，不压缩输入控件的必要宽度，也不改变窗口标题栏预留、表格列宽和主从栏宽等功能性尺寸。

## 4. 操作颜色语义

| 语义 | 样式 | 示例 |
| --- | --- | --- |
| 主操作 | `Primary` | 保存、创建、运行、查询、迁移 |
| 中性操作 | 默认按钮 | 取消、关闭、返回、重新加载 |
| 危险操作 | `Danger` | 删除、删除数据、清空、覆盖不可恢复内容 |

“禁用”是否使用危险样式取决于数据是否保留。保留数据且可以立即恢复的启停操作保持中性；会删除本地或远程数据的操作必须使用 `Danger`。

## 5. 文案规范

- 产品名称统一写作 `Redmine`，代码类型名暂不重命名；
- 凭据字段统一写作 `API Key`；
- “关闭”只表示退出页面，“删除”或“删除数据”明确表示数据影响；
- 错误提示应同时描述问题和下一步操作。

## 6. 自动化验收

CDP 视觉回归至少覆盖 1280×800 深色主题：

- 工具栏控件中心线偏差不超过 2px；
- 设置窗口最后一组仍为“AI 与 MCP”；
- 对话框底部操作区完整可见；
- DataGrid 操作列不被裁剪；
- 空状态、错误状态和只读状态没有重叠；
- 页面头、主卡片和嵌套卡片之间保持稳定的 4～10px 层级间距，边框不粘连，内容不因压缩而裁切；
- 页面头和区块中的标题/说明优先左右排列并保持底边偏差不超过 2px；长说明使用信息图标 Tooltip 时，图标不得挤压标题或右侧操作；
- 事项状态胶囊必须按未保存、待同步、已同步、失败、待确认和中性状态使用对应语义色，并在浅色、深色主题下保持文字清晰；
- 日期标题下方的主操作分别贴齐操作区左右边缘；一周日历在 150% DPI 下无裁切；今天使用圆形浅色强调底与描边、当前选中使用圆形主色高亮背景，悬停和按下反馈同样保持圆形且可叠加；右键非选中日期后按钮保持稳定并打开菜单，月份标题通过鼠标右键、`Shift+F10` 和系统上下文请求均可打开月/季度/年度菜单，完整月历按模板自然测量，外层宽高不得小于内部模板，最后一行与四周边框完整可见且不承载右键操作；从年份视图关闭后再次展开必须恢复月视图，点击日期后弹层立即关闭，相邻月份日期只推进到目标月份并更新日期标题；日期、标题和耗时输入框左边缘偏差不超过 1px；事项编辑器的单个“从模板更新”分段按钮紧跟“使用今天”，主体用于更新，右侧下拉菜单提供“应用模板”，且不改变日期控件左边缘；
- Redmine 样式检查只执行读取和页面导航，不创建 Issue、不导入问题、不提交工时。
- 固定宽度对话框中的标题、副标题、长 ID 和底部操作不得横向溢出；长详情必须通过局部滚动访问。
- 占用剩余空间的只读预览文本框必须显式双向拉伸、内容顶部对齐并保留滚动条；生成内容前后不得按文本期望高度居中缩放或发生尺寸跳变。
- 日记事项备注等可编辑长文本区域必须显式双向拉伸、内容顶部对齐并保留合理最小高度；所在卡片获得额外高度时，编辑框应填满剩余内容区，不得按最小高度垂直居中。
- “Tracker 关联”属于按能力出现的区块；没有启用且成功创建的 Tracker 编辑扩展时必须隐藏整个卡片，不显示空标题、说明或分隔线。
- 紧凑周历的中央年月按钮同时显示年度周次，格式为 `yyyy年M月 第X周`；周次口径必须与日期上下文菜单一致，导航和日期选择后不得保留旧周次。
- `Name`、命令、快捷键、页签文字和关键按钮原文案属于自动化及兼容性契约，视觉重构不得随意改名。

## 7. 迁移顺序

1. 收敛公共样式、按钮语义、Redmine 命名和明确的对齐问题；
2. 统一日记、查询和统计工作台；
3. 迁移程序设置、标签、模板、数据模板和 Tracker 设置；
4. 统一 Jira/Redmine 实例配置、编辑区域及 Redmine 动态管理页；
5. 通过功能 CDP、只读视觉 CDP 和最终截图复检收口。
