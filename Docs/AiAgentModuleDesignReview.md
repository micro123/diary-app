# 可选 AI Agent 模块详细设计评审

## 1. 评审信息

- 评审日期：2026-10-19
- 评审对象：[`AiAgentModuleDesign.md`](AiAgentModuleDesign.md)
- 需求基线：[`AiAgentModuleRequirements.md`](AiAgentModuleRequirements.md)
- 产品定位：个人或小团队的日常工作记录助手
- 结论：**实现通过；阶段 A、P0、P1 和首版 MCP Client 已完成**
- 实施跟踪：2026-10-08 已通过自动化、CDP UI、Windows/Linux 发布和私有加载上下文门禁；仅真实内部 DeepSeek/GLM 探测等待外部连接参数

本轮修订明确：标题、日期、时长、标签、模板、附加字段和 Tracker 摘要等普通工作数据可以提供给用户配置的模型；唯一默认禁止读取和发送的工作内容是工作项本地备注。

因此，P0 不再引入模型信任域、工具结果数据分级、逐请求披露守卫、系统 Secret Service 强制依赖或搜索词逐次外发确认。后续若产品进入多租户、强合规或开放第三方模块场景，再单独补充企业级安全设计。

## 2. 评审范围和方法

评审覆盖：

1. 当前 DiaryApp 的 DI 构建、程序集扫描、导航、设置和 ViewLocator；
2. AI 模块未安装或禁用时的隔离；
3. OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 的流式响应和工具调用闭环；
4. DeepSeek、GLM、多连接和代理配置；
5. 工作项本地备注排除边界；
6. 内置工具、网页工具和后续 MCP Client；
7. 写操作预览、确认和幂等；
8. 发布、测试和分阶段实施范围。

## 3. 总体评价

设计与当前产品定位匹配，主要优点包括：

- AI 是独立可选模块，没有被建模为 Tracker，也不会成为核心启动依赖；
- manifest-first 发现和 DI 构建前注册符合当前应用启动方式；
- 协议适配层覆盖 Chat Completions、Responses 和 Anthropic Messages，内部 DeepSeek、GLM 不需要厂商专用客户端；
- Agent 只通过注册工具访问宿主能力，不直接操作数据库、文件或 Shell；
- 隐私边界已收敛为清晰、可测试的一条规则：不读取工作项本地备注；
- 凭据复用现有认证加密能力，不额外引入系统密钥环的 P0 依赖；
- P0 保持只读，写入延后到稳定命令契约和确认流程完成之后；
- 网页访问保持为受控的 `web_search`/`web_fetch`，不向模型暴露原始 HTTP 客户端；
- MCP Client 保持 P2，不阻塞普通网页访问和 P0 Agent。

设计不再按企业数据防泄漏系统建设，避免了与实际使用场景不匹配的权限、审计和确认成本。

## 4. P0 实现门禁

以下项目不是新的产品决策，但必须由实现和测试证明。

### G-01：禁用模块不得被加载

- 模块使用独立目录和 manifest-first 发现；
- 只有启用且兼容的模块才加载入口程序集；
- AI DLL 不进入应用根目录的 `Diary.*.UI.dll` 全量扫描范围；
- 模块损坏或不兼容不能阻止核心 App 启动。

### G-02：本地备注必须在宿主适配层排除

- Agent 工具不得调用 `WorkGetNote` 或 `GetWorkNotesByWorkItemIds`；
- 工作项工具 DTO 不定义本地备注字段；
- 本地备注不得进入模型请求、工具结果、会话持久化或日志；
- 需要增加带唯一标记备注的端到端回归测试，验证模型请求体中不存在该标记。

仅依赖 Prompt 告诉模型“不要读取备注”不满足门禁，必须由本地代码根本不读取该字段。

### G-03：凭据不得进入普通日志和模型消息

- API Key、代理密码和认证 Header 通过 `IAiCredentialStore` 保存；
- P0 默认实现可以复用现有认证加密文件；
- UI 不回显完整凭据；
- 日志、诊断导出、AI 上下文快照和模型消息不包含凭据正文。

这是一项基本工程约束，不要求 P0 接入 Windows Credential Manager 或 Linux Secret Service。

### G-04：协议和工具调用需要真实兼容性验证

三种协议适配器都需要通过模拟服务验证：

- 非流式对话；
- 流式文本；
- 流式工具参数拼接；
- 工具调用与工具结果的多轮配对；
- 取消、超时、认证失败和代理失败。

Responses 还必须验证 `output` Items、`call_id`、`function_call_output` 和 `store=false` 下的应用侧会话状态；Anthropic Messages 必须验证 content blocks、tool use/result 和 `input_json_delta`。内部 DeepSeek、GLM 按实际暴露的协议完成真实连接测试。

不支持工具调用的连接应自动降级为普通对话，不阻止其他连接使用 Agent 模式。

## 5. 后续阶段门禁

### 5.1 P1 网页工具

网页能力发布前至少满足：

- 仅支持 HTTP/HTTPS 和 GET/HEAD；
- 公网模式拒绝明确的 localhost、链路本地、私网和元数据地址；
- 每次重定向重新检查目标；
- 跨主机重定向不转发认证 Header；
- 内部站点只能在用户显式配置后访问；
- 响应大小、正文长度、重定向和超时有明确上限；
- 页面文本不能直接改变工具启用状态或触发写操作。

不要求 DiaryApp 验证公司代理的完整出口策略，也不要求搜索词逐次确认。

### 5.2 P1 事项写入

完整事项写入仍需要新增稳定的 `IWorkItemCommandApi`，由宿主实现并复用现有持久化协调器。发布前必须验证：

- 展示实际写入字段；
- 用户确认后执行；
- 预览版本过期时要求重新确认；
- 幂等键防止重复创建；
- 标签、附加字段和事务失败能够正确回滚。

删除事项继续不向 Agent 开放。已保存脚本执行和 Tracker 工时提交在 P2 以独立默认关闭开关、逐次确认、幂等和受控宿主契约实现；脚本只允许执行脚本目录中已加载的 ID，不接受模型当轮源码，Tracker 提交在首个失败处停止且不允许修改 Tracker 配置。

### 5.3 独立模块发布

P0 可以采用“随主程序发布、默认禁用”，因此独立模块安装不阻塞 P0。

如果以后提供独立下载安装，则需要补充：

- 模块包版本和 App 兼容范围；
- 原子替换和失败回滚；
- 完整 App 更新时的模块目录所有权；
- 官方包签名或可信更新清单。

这些要求只约束独立发布，不要求首个可用版本立即实现。

## 6. 高优先级实现建议

### H-01：共享程序集列表集中维护

独立 `AssemblyLoadContext` 必须复用宿主的模块契约、Avalonia 和 DI 抽象，避免加载第二份契约程序集造成类型身份不一致。

### H-02：设置页使用显式贡献接口

AI 设置包含连接列表、连接测试、代理和凭据状态，应使用 `ISettingsContribution` 提供独立 ViewModel，不继续扩展反射配置树。

### H-03：流式显示与已提交历史分离

流式文本可以实时显示，但只有收到完整协议结束事件后才写入可重放的 assistant 消息。中途取消或断线的显示缓冲不能直接作为下一轮历史。

### H-04：工具快照在单次 run 内不可变

每次 run 捕获连接版本、已启用工具和预算。运行期间修改设置只影响下一次 run，避免模型看到的工具列表与实际执行列表不一致。

### H-05：搜索 Provider 未配置时隐藏工具

没有 `IWebSearchProvider` 时，不应向模型注册一个必然失败的 `web_search`。

### H-06：连接编辑使用 working copy

连接测试失败不应覆盖当前可用配置；只有用户保存并通过校验后才替换运行时客户端。

## 9. 实施复评结论

详细设计已经与“日常工作记录助手”的实际定位对齐，**评审通过**。

实现已完成通用模块基础、P0、P1 与首版 MCP Client，并保持首轮评审确定的轻量边界。系统 Secret Service、企业级数据分级、逐请求披露守卫、复杂出口治理、浏览器自动化和独立模块签名仍不作为首版发布前置条件。

实现时必须守住三条简单边界：

1. AI 模块禁用时不加载、不联网；
2. 工作项本地备注不读取、不发送、不记录；
3. API Key、代理密码和认证 Header 不进入日志或模型消息。

写操作继续要求应用侧校验和用户确认，这是数据正确性要求；网页工具保留基本地址和重定向检查，这是避免误访问本机服务的工程边界。两者都不扩展为企业级权限平台。

最新增量复评已执行 Agent 151/151 和全解决方案 Release 构建，覆盖模型连接共享包凭据剥离、三协议与兼容配置往返、冲突改名、严格输入拒绝，以及最新请求上下文估算、服务端 usage 修正、工具多轮与无 usage 回退、运行时日期时区注入、跨 run 刷新、三协议系统字段、只读时间工具、长期记忆存储、压缩后保留、旧设置默认值、空设置损坏保护、确认拒绝/冲突、备份恢复和记忆工具参数摘要隐藏。Script 247/247、App 341/341、当前 Windows 可运行的数据库测试 162/162、AI CDP 7/7 以及 `win-x64`/`linux-x64` 自包含发布属于此前已记录证据，本次未重复执行；数据库测试另有 113 项因 PostgreSQL/Docker 不可用或平台条件跳过，0 项失败。端到端回归会把唯一备注标记放入宿主结果并检查实际模型请求体不存在该标记。内部 DeepSeek/GLM 的实网探测需要部署方提供实际地址、模型名、协议和凭据；未提供前不得宣称已通过真实内部服务验收。

## 10. Agent 长期记忆增量评审

2026-10-19 对长期记忆增量设计复评，结论为通过。该能力不修改数据库、工作项模型或会话持久化结构，保持可选 AI 模块边界：模块禁用时不会创建或读取记忆存储。

评审确认以下决策：

1. 使用模块配置目录下固定的 `memory.md`，而不是模型可指定的任意路径；
2. 使用 UTF-8 Markdown 和 32 KiB 上限，便于用户直接检查和修改；
3. 记忆注入默认启用，Agent 写入权限默认关闭；用户手工编辑不经过模型确认，模型提议写入必须逐次确认；
4. 写入展示更新原因和前后全文，确认后使用内容版本校验，冲突时拒绝覆盖；
5. 写入采用临时文件原子替换并保留一个 `.bak`，设置页提供恢复入口；
6. 记忆只在 run 开始时读取一次，压缩后继续注入，但不进入会话、压缩摘要、思考、审计正文或普通日志；
7. 当前用户请求和应用系统规则优先于长期记忆，工作项本地备注不得自动成为记忆来源；
8. 不实现自动从对话提取、向量检索、语义合并或跨设备同步，后续确有需求时另行设计。

门禁测试必须覆盖三协议系统字段、自动压缩后的重新注入、旧设置默认值、UTF-8/大小限制、拒绝无副作用、确认期间外部修改冲突、备份恢复，以及会话投影中不存在记忆正文。

## 11. Agent 上下文占用显示增量评审

2026-10-19 对上下文占用显示增量设计复评，结论为通过。该能力只增加运行时事件和页面状态，不修改数据库、工作项核心结构或会话文件格式。

评审确认以下决策：

1. 页面显示最新一次模型请求的上下文，不使用整轮 Agent run 的累计计费量；
2. 已用量按输入上下文加本轮最大输出预留计算，总窗口来自当前连接配置；
3. 请求发送前先显示本地估算，服务端返回输入 usage 后以该次请求的实际值修正；
4. 兼容模型服务未返回 usage 时保留估算值和 `≈` 标识，不因此阻断 Agent；
5. 工具多轮每轮刷新，最终保留最新请求；新建、恢复会话和切换连接时清除旧请求占用；
6. Tooltip 展示输入、输出预留、窗口、压缩阈值和来源，75%/90% 分别使用警告和危险颜色；
7. 上下文占用不持久化，累计 usage 继续只用于会话统计和计费诊断。

门禁测试覆盖工具两轮时实际输入值与累计 usage 分离，以及模型服务不返回 usage 时保留本地估算。

## 12. 模型连接共享包增量评审

2026-10-19 对模型连接导入/导出增量设计复评，结论为通过。该能力仅操作 AI 设置 working copy 和用户选择的共享文件，不修改数据库、工作项核心结构、会话格式或现有 AI 设置 schema。

评审确认以下决策：

1. 使用独立版本化 `.diaryaiconnections` DTO，不直接序列化持久化设置对象；
2. 导出服务不依赖 `IAiCredentialStore`，分享 DTO 不存在 Credential Reference 字段，从结构上阻止读取和输出 API Key、代理凭据及秘密 Header 引用；
3. 普通额外 Header 值视为非秘密配置保留，秘密值必须使用 Credential Reference；用户手册对此给出明确警告；
4. 导入只追加 working copy，不覆盖、不自动设默认、不携带能力探测缓存；ID 冲突使用 `-imported` 系列后缀；
5. 导入根据最终 ID 生成新的本机凭据引用，用户必须补填凭据、重新测试并保存后才生效；
6. 严格拒绝未知格式/版本/字段、数字枚举、null 必需对象、重复 ID、非法 URL、错误凭据标记、超过 100 个连接或超过 1 MiB 的包；任一错误都不允许部分导入；
7. 设置编辑器必须保留不可见的兼容选项，避免通过 UI 导出时把已有兼容配置还原为默认值。

门禁测试覆盖三种协议、认证/代理/额外 Header 凭据剥离、新凭据引用生成、普通 Header 和兼容选项往返、冲突改名以及恶意或损坏输入拒绝。完整 Release 构建负责验证 Avalonia 文件选择器、命令生成、XAML 绑定和依赖注入。
