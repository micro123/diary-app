# 脚本共享包设计

## 1. 目标

脚本管理页支持把多个 C#、Lua、Python 脚本一次导出为单个共享包，并在另一套 DiaryApp 中预览后批量导入。共享包用于源码分发，不承担在线仓库、依赖下载、数字签名或自动更新职责。

导入动作本身不执行脚本。导入完成后宿主重新加载目录并展示正式构建诊断；自动化脚本随后会按导入的运行配置参与正常调度，因此 UI 必须明确展示入口类型并提醒只导入可信来源。

## 2. 文件格式

扩展名为 `.diaryscripts`，物理格式为 ZIP。根目录只允许出现 manifest 声明的文件：

~~~text
manifest.json
scripts/000/example.cs
scripts/000/metadata.json
scripts/001/example.py
~~~

`manifest.json` 使用 snake_case，关键字段：

- `format`：固定为 `diary.script.package`。
- `format_version`：当前为 1，与 Script API 版本相互独立。
- `created_at`：UTC 导出时间。
- `scripts`：脚本描述数组，包含 id、name、scope、entry_kind、language、原始文件名、包内源码/metadata 路径及 SHA-256。

源码是必需项；同目录 `<source>.json` 存在时作为运行配置一并导出。若脚本来自带 `manifest.json` 的脚本子目录且源码旁没有 metadata，导出端会把加载器已经解析的有效 metadata 规范化写入共享包，确保依赖 metadata 的 Lua/Python 脚本仍可独立导入。导入后 metadata 恢复为目标源码路径加 `.json`。

## 3. 用户流程

### 导出

1. 在脚本管理页点击“导出共享包”。
2. 对话框默认选中当前已发现的全部脚本，可全选或清空后重新勾选。
3. 选择保存位置，宿主原子生成单个共享包。

### 导入

1. 在脚本管理页选择一个 `.diaryscripts` 文件。
2. 宿主完整校验包格式、路径、大小、校验和和目标位置。
3. 预览对话框显示语言、作用域、入口类型和冲突状态。
4. 无冲突项默认选中；冲突项默认跳过，用户主动勾选才授权覆盖。
5. 导入完成后重新加载脚本目录，并以正式构建结果决定脚本是否可用。

## 4. 冲突策略

- 相同 ID 且语言、作用域一致：允许用户显式原位覆盖，保留现有源码文件名。
- 相同 ID 但语言或作用域不同：拒绝导入，要求先手动删除旧脚本，避免一次导入跨目录删除或改变语言。
- 没有相同 ID，但目标文件名已存在：标记为冲突，只有用户显式勾选才覆盖。
- 覆盖同时替换源码和 metadata；包中没有 metadata 时会移除旧 metadata，使目标与共享包保持一致。

批量写入使用备份目录记录被替换文件。任一项目失败时删除本轮新文件并按逆序恢复备份，避免半导入状态。

## 5. 安全边界

- 单包最多 200 个脚本。
- 压缩包和总解压内容最多 50 MiB。
- 单个源码最多 2 MiB，单个 metadata 和 manifest 最多 1 MiB。
- 不执行整包解压，只读取 manifest 明确引用的条目。
- 拒绝绝对路径、反斜杠路径、空路径段、`.`、`..`、重复条目和未声明文件。
- 仅接受 `.cs`、`.lua`、`.py`，并校验声明语言与扩展名一致。
- 每个源码和 metadata 使用 SHA-256 检查完整性。
- metadata 必须是 JSON 对象。
- 所有目标路径必须保持在应用脚本根目录内。

SHA-256 只能发现损坏或篡改，不能证明发布者身份。当前共享包没有数字签名或信任链。

## 6. 版本演进

共享包版本独立于 `ScriptApiVersion`。未来新增字段应保持 format_version 1 的向后兼容；只有无法兼容的结构变化才增加 format_version。导入端必须拒绝未知主版本，不能猜测字段语义。

## 7. 测试要求

- 多脚本、跨作用域和 metadata 往返。
- 冲突默认跳过与显式覆盖。
- 源码校验和损坏。
- manifest 路径穿越。
- 文件数、大小、重复 ID、未知语言和未声明条目。
- 批量写入失败后的备份恢复。
- 导出/导入对话框的默认选择与冲突授权语义。
