# 工时记录日历设计

## 1. 目标

日记页需要在不离开工时记录流程的情况下，直观看出可见日期是否已经填写工作项，并允许用户按个人习惯在周视图和月视图之间切换。月视图不能固定占用六行高度，而应按月份实际覆盖的完整周显示 4 至 6 行。

本功能不修改 `WorkItem`、核心数据库表或数据版本。日期填报状态属于查询结果和界面状态，不作为业务字段持久化。

## 2. 交互设计

- 程序设置的“视图设置”提供“工时日历视图”，可选择周视图或月视图，默认沿用原有周视图。
- 周视图显示锚点所在周的周一至周日；上一周期、下一周期、PageUp/PageDown 和滚轮均按周切换。
- 月视图从当月第一天所在周的周一开始，到当月最后一天所在周的周日结束，实际显示 28、35 或 42 天；周期导航按月切换。
- 绿色实心点表示当天至少存在一条已保存工作项；没有记录的日期保持空白，不额外显示缺失标记。
- 程序设置中的“显示每日记录数”开启后，在有记录日期右上角最上层显示白字绿底的数字角标，并隐藏该日期原有的绿色实心点；关闭后只显示填报状态点。角标使用无边框圆形背景，不会被日期选中、今日或悬停状态遮挡。
- 日期 Tooltip 展示日期、条目数和总工时；未来日期显示“尚未到达”。
- 点击日期、键盘方向导航、日期右键菜单、标题完整月历和周期上下文菜单继续沿用现有命令。月份标题保留 `PointerPressed` 以兼容各平台鼠标右键，后续 `ContextRequested` 检测到菜单已经打开时只消费事件，不再重复打开和二次定位；`Shift+F10` 保留独立键盘入口。
- 视图模式和数量开关随程序设置保存到现有 `app_settings.json`，保存后当前日记页立即刷新，不需要重启，也不进入数据库。

## 3. 组件边界

`WorkRecordCalendar` 是日记页内的独立 Avalonia `UserControl`，负责布局、完整月历弹层、键盘、滚轮和上下文菜单事件。`DiaryEditorViewModel` 负责可见日期范围、按日汇总状态、选中日期和用户偏好。

控件不直接访问数据库。ViewModel 根据当前模式计算一个连续范围，并通过 `DbInterfaceBase.GetWorkItemDaySummaries` 获取汇总结果。

## 4. 数据访问

按日汇总接口输入闭区间起止日期，返回：

- 日期；
- 工作项数量；
- 总工时。

SQLite 与 PostgreSQL 使用 `GROUP BY create_date`、`COUNT(*)` 和 `SUM(hours)` 在数据库内聚合，因此周视图最多返回 7 条、月视图最多返回 42 条，不需要把范围内全部工作项加载到应用内存。抽象基类保留基于现有范围查询的兼容实现，便于测试替身和后续 provider 接入。

保存、复制、删除、日期重新加载和数据库变更后会重新读取当前可见范围，确保状态与条目数及时更新。

## 5. 兼容性与验收

- 不新增数据库迁移，不改变数据版本。
- 原有配置缺少新字段时默认使用周视图且不显示数量。
- SQLite/PostgreSQL 契约测试验证日期分组、数量、工时和闭区间过滤。
- 日历测试验证周一开始、周视图 7 天、月视图 4/5/6 行和标题格式。
- Release 构建必须通过 Avalonia 编译绑定和 XAML 编译。

本功能验证期间实际遇到的并行 MSBuild 文件锁、.NET 10 `dotnet test --project` 参数和 Debug CDP 条件 restore 问题已归档到 [`DevelopmentVerificationGuide.md`](DevelopmentVerificationGuide.md)，后续验证应直接复用其中的串行命令和错误判定口径。
