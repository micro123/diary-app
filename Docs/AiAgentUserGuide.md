# AI 助手用户指南

## 1. 启用模块

AI 助手随 DiaryApp 发布，但默认禁用。打开标题栏设置菜单中的“模块设置”，在“模块管理”页启用“AI 助手”，保存后重启应用。模块管理页同时显示当前加载状态、启动诊断和是否存在待重启变更。

模块状态保存在应用配置目录中的 `module-states.json`，等价配置如下：

```json
{
  "schemaVersion": 1,
  "modules": {
    "diary.ai-agent": {
      "enabled": true
    }
  }
}
```

Windows 默认配置目录是 `%APPDATA%\Diary.App`，Linux 默认是 `~/.config/Diary.App`。启动参数 `--core-only` 会忽略所有可选模块，适合模块故障排查。删除 `Modules/diary.ai-agent` 后，核心 DiaryApp 仍可独立运行。

## 2. 添加模型连接

打开“模块设置 → 模块配置 → AI 助手设置”，新增连接并填写：

- 协议：OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages；
- Base URL、可选路径覆盖和模型名；
- 认证方式、Header 名称和前缀；
- 系统代理、直连、自定义代理或继承 AI 默认代理；
- 默认开启的证书吊销状态检查；若可信内网无法访问证书 CRL/OCSP，且连接测试报告 `tls_revocation_offline`，可仅对该连接关闭；
- 可选额外 Header JSON。

连接测试使用 working copy，不会在失败时替换已保存配置。“测试连接”只发送一次最小非流式请求，最多等待 30 秒，适合快速检查地址、路径、代理、TLS、认证和模型；成功后显示“基础连接成功”，但尚未开放 Agent 工具。“完整能力探测”最多运行 90 秒，依次验证普通对话、流式文本、普通与流式工具闭环、并行工具调用和强制工具选择，界面显示当前阶段，可随时点击“取消测试”。只支持聊天的连接会显示“普通对话”，不会收到 DiaryApp 工具；普通工具闭环通过后即可显示“Agent 模式”，流式工具、并行工具和强制工具属于可选增强能力。后续阶段超时时保留此前已经验证的结果：工具闭环已通过则继续使用 Agent 并自动降级，尚未通过则仍可普通聊天。带工具请求只有在流式工具探测通过时才使用流式协议，否则自动改用非流式工具闭环。“复制”只复制非秘密配置，API Key 和代理凭据必须重新填写。

AI 助手输入框支持 `Enter` 或 `Ctrl+Enter` 发送，使用 `Shift+Enter` 插入换行；运行期间仍可点击“停止”取消当前请求。

关闭“检查证书吊销状态”只会跳过 CRL/OCSP 查询，证书信任链、域名、有效期等 TLS 校验仍然保留。不要用它处理自签名证书或域名不匹配；这类问题应将内部 CA 安装到系统信任库或修复服务端证书。

## 3. 凭据

凭据正文不会写入 `settings.json`，也不会在 UI 中回显。Credential Reference 支持：

- `diary.ai/...`：保存到 DiaryApp 现有加密凭据文件；
- `env:VARIABLE_NAME`：从环境变量只读获取；
- `memory:...`：仅当前进程有效，主要用于临时测试。

设置页会显示“已保存”“未保存”“来自环境变量”“环境变量未设置”或“无需凭据”。额外 Header 若需要秘密值，应填写 `credentialReference`，不要把 Token 直接写入 `value`。删除连接时可选择在设置保存成功后清理该连接独占且不再被其他连接引用的 `diary.ai/...` 或 `memory:...` 凭据；重新加载未保存的修改不会提前删除凭据，环境变量引用和共享凭据也不会删除。

## 4. 工具和数据边界

工具按每次运行开始时的设置生成不可变快照：

- Diary 只读工具：查询事项、按 ID 读取事项详情、统计分析、附加字段目录、记录质量分析、周期对比、日历概览、查询导出格式/模板、标签、事项模板、Tracker 实例和当前上下文；
- 确认后写入工具：创建、单项/批量更新事项、从模板创建事项、导出日报/周报、写入剪贴板和发送应用通知；
- 网页读取：受控静态 `web_fetch` 和系统浏览器动态 `web_render_page`；
- 网页搜索：只有安装了 `IWebSearchProvider` 才会出现；
- MCP 工具：只公开本地配置中逐项启用的远端工具。

工作项本地备注不会被 Agent 查询 API 读取，也不会进入只读工具结果、模型请求、会话文件或审计日志。创建事项时，模型提出的新备注会在确认卡片中显示，并且只有用户确认后才写入。

模型不会获得原始数据库连接、任意 SQL、Shell、任意文件、原始 `HttpClient`、浏览器 Cookie、点击、表单提交或文件上传能力。

Agent 不提供页面跳转、日期切换、事项选择或筛选等 UI 操作工具，也不提供任何删除工具。MCP 中声明的删除类工具同样不会因为用户确认而自动获得权限；设置保存和工具注册都会拦截名称中带有常见删除语义的工具。若某个外部工具名称无法表达真实副作用，不应把它配置为只读工具。

### 4.1 自动上下文压缩

每个模型连接可以配置“窗口 Token”“自动压缩”和“阈值 %”。默认按 128 Ki Token 窗口、75% 阈值自动压缩；内部 `deepseek-v4-pro` 等实际支持 1M 上下文的连接应把窗口填写为 `1000000`，模型名称仍只填写真实名称，不附加 `[1M]`。

发送消息前，应用会估算历史消息、工具定义、Responses 协议状态和预留输出占用。达到阈值时，保留最近两轮完整对话，把更早轮次合并为结构化摘要；摘要失败会使用本地兜底摘要，不阻断本轮请求。状态栏会显示自动压缩，完成状态会显示当前会话累计压缩次数。

摘要作为历史数据加入系统指令，不能覆盖安全规则或授权写工具。保存会话时只保存摘要及压缩后保留的消息，恢复会话不会重新加载已被摘要替代的完整历史。

## 5. 写入确认

启用“确认后写入工具”后，以下内置工具会加入下一次 Agent 运行的不可变工具快照：

- `diary_create_work_item`：创建完整事项；
- `diary_update_work_item`：更新事项的日期、标题、工时、优先级、标签和标签附加字段；
- `diary_batch_update_work_items`：一次确认后原子更新 1–20 个事项；
- `diary_create_from_template`：按模板创建事项；
- `diary_export_report`：把指定日期或所在周的事项导出为已安装格式；
- `diary_set_clipboard_text`：写入系统剪贴板；
- `diary_notify`：发送 DiaryApp 会话级通知。

`diary_create_work_item` 先生成宿主预览，确认卡片展示日期、标题、工时、优先级、标签、备注和附加字段。可选择：

- 确认：使用当前预览版本写入；
- 编辑后确认：重新预览编辑后的命令再写入；
- 拒绝：不产生副作用，并把拒绝结果返回模型完成工具闭环。

`diary_update_work_item` 的通用确认卡会展示修改前后字段，包含待修改的标签附加字段，确认执行时再次检查预览版本；它不能修改或读取本地备注，也不能删除事项。附加字段采用局部更新：不传 `extraFields` 会保留仍属于当前标签的值，只传需要修改的字段即可，空白值用于清空指定字段；移除标签会清理该标签对应的字段值。

`diary_batch_update_work_items` 在一张确认卡中逐项展示修改前后内容，每批最多 20 项。确认后应用会重新检查整个批次并在一个数据库事务中保存；任一事项失败时全部回滚，不会留下部分更新。整批共用一个幂等键，重复调用不会重复写入。`diary_create_from_template` 会在确认卡中展示模板名称、默认标签 ID 和预览结果，确认后再次预览并使用幂等键执行。

`diary_export_report` 支持日报和周报，数据只包含日期、标题、工时、优先级和标签。模型可以选择已安装的导出格式和安全文件名，但不能指定任意目录；文件写入应用配置目录下的 `ai-agent/exports`，确认后若事项数据发生变化会要求重新预览。导出模板查询目前用于能力发现，Agent 报告导出使用统一表格内容，不自动套用模板。剪贴板和通知工具同样只有选择“确认调用”后才调用宿主 API。

没有“永久跳过确认”。拒绝、停止生成、取消运行或关闭模块都会清除待确认操作而不产生副作用；预览过期、标签或字段定义变化、持久化失败都会拒绝写入，幂等键防止重复创建、单项/批量更新或导出。删除事项和 UI 控制不会向 Agent 开放；执行脚本和提交 Tracker 工时当前仍未开放。

## 6. 网页访问

`web_fetch` 只允许 GET/HEAD 的 HTTP/HTTPS 目标。默认允许 loopback 和常见内网地址，以便访问本机服务与公司内网页面；链路本地、组播、保留、测试网段和已知云元数据地址仍会拒绝。每次 DNS 解析、实际连接和重定向都会重新校验。需要限制端口或附加认证 Header 的内部站点仍可通过 `internalSites` 显式配置。

认证只发送给配置的 origin，跨 origin 重定向会移除认证。响应受 Header、压缩体、解压体、字符数、重定向和总超时预算限制。静态 HTML 会移除脚本、样式、表单和隐藏内容，并把结果标记为外部不可信内容；网页文字不能改变工具策略或自动触发写入。

`web_render_page` 用于 `web_fetch` 无法读取的 JavaScript 动态页面。默认自动检测本机 Edge、Chrome 或 Chromium，使用随机本地 CDP 端口和独立临时 Profile 启动；DiaryApp 不下载浏览器，也不会连接用户正在使用的默认 Profile。工具只导航页面并执行应用内固定的正文提取逻辑，不支持模型指定 JavaScript、点击、输入、表单、上传下载或读取 Cookie。图片、媒体、字体、Manifest、Ping 和 WebSocket 默认不加载，所有主页面和子资源 URL 都要通过同一网页访问策略。

“网页访问策略”中的浏览器配置示例：

```json
{
  "allowPrivateNetwork": true,
  "allowLoopback": true,
  "browser": {
    "mode": "System",
    "executablePath": null,
    "cdpEndpoint": null,
    "headless": true,
    "renderDelayMilliseconds": 750,
    "maxLinks": 100
  }
}
```

`allowPrivateNetwork` 和 `allowLoopback` 可分别关闭内网与本机地址访问；关闭后仍可用 `internalSites` 按 host 和端口精确放行。`mode` 可选 `Disabled`、`System`、`Executable` 或 `Cdp`。`Executable` 必须填写浏览器程序路径；`Cdp` 只接受本机 HTTP(S)、`ws` 或 `wss` Endpoint。找不到系统浏览器时，动态工具会返回明确错误，静态 `web_fetch` 仍可使用。系统代理、直连、自定义代理和代理凭据继续由同一网页访问策略控制。

## 7. MCP Client

支持：

- stdio：直接启动可执行文件，不经过 Shell，子进程窗口隐藏；
- Streamable HTTP：JSON 或 SSE 响应、`Mcp-Session-Id`、GET 通知流、独立代理和认证。

配置必须为每个远端工具声明本地策略。未列入策略的工具不会向模型公开；`ReadOnly` 直接调用，`Write` 每次显示确认卡片，`Destructive` 在首版配置校验中被拒绝。服务器自己的工具注解不授予权限。

## 8. 会话与审计

会话保存用户消息、最终回答、连接、模型、工具名、脱敏参数摘要、状态、来源、耗时和 usage，不保存完整工具结果、隐藏推理、认证 Header 或服务端私有状态。最多保留 50 个会话；损坏文件只读为空且禁止覆盖。

审计记录 run 和工具的结构化元数据，默认单文件 5 MiB、保留 3 个轮转文件。只有受信任的内置工具可以记录安全的效果摘要。审计写入失败不会改变 Agent 运行结果。

## 9. 发布与故障排查

AI 私有文件只位于 `Modules/diary.ai-agent`：

```text
module.json
Diary.Agent.UI.dll
Diary.Agent.UI.deps.json
Diary.Agent.dll
AngleSharp.dll
```

常见处理：

- 页面没有 AI 导航：打开“模块设置”检查启用状态和启动诊断，然后重启；
- 显示普通对话：重新测试连接，确认服务支持完整工具调用和结果回传；
- 连接测试失败或超时：状态会显示错误码；打开 `%LOCALAPPDATA%\Diary.App\Diary.App.log` 或在程序设置中导出日志，按连接 ID、协议、Base URL、代理模式、错误类别和 HTTP 状态定位，日志不包含凭据；
- 完整能力探测耗时较长：查看当前阶段，最多等待 90 秒；可点击“取消测试”，取消后不会继续后续探测；
- 407：配置代理凭据并确认 Credential Reference 状态；
- 网页目标被拒绝：不要放宽全局策略，只为确需访问的内部 host/端口增加白名单；
- 设置文件损坏：先备份和修复原文件，应用会阻止覆盖；
- 模块导致启动异常：使用 `--core-only` 启动；修复后正常启动并在“模块设置 → 模块管理 → 启动诊断”中查看原因。

内部 DeepSeek/GLM 使用与其网关实际暴露格式一致的协议连接。真实验收必须由部署方提供 Base URL、路径、模型名、认证和代理条件；不要用厂商名称猜测协议。
