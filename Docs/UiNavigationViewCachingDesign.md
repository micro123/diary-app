# 主导航 View 实例缓存设计

## 1. 目标

主导航页面在首次打开后应复用已经创建的 Avalonia View，减少重复解析 XAML、创建控件树和建立绑定带来的热切换延迟。同时必须限制缓存范围，避免日记页中数量可能很大的事项编辑器、对话框和 Tracker 编辑区域长期驻留。

本设计采用“每个 ViewModel 实例对应至多一个可缓存 View 实例”，不按 ViewModel 类型共享 View。这样可以保留每个页面实例自己的绑定状态，也不会让同类型但不同业务实例错误共用视觉树。

## 2. 缓存资格契约

`ViewModelBase` 提供默认关闭的虚属性：

```csharp
public virtual bool IsViewCacheable => false;
public virtual Task PreloadAsync(CancellationToken cancellationToken = default) => Task.CompletedTask;
```

View 缓存是显式加入能力。普通 ViewModel 无需覆盖该属性，默认不会进入缓存；只有生命周期稳定、实例数量受控的主导航页面才覆盖并返回 `true`。这样既保持安全默认值，也避免对话框、编辑器和第三方插件派生类被迫实现机械性的 `false`，并降低公共基类的兼容性成本。

`PreloadAsync()` 是独立的可选预加载契约。默认实现不执行工作；需要准备后台数据的缓存页面可以覆盖，但不应在其中调用 `OnShow()`、弹出 UI 或假定页面已经可见。导航宿主会等待预加载任务，再完成隐藏 View 的布局；取消只停止宿主等待，不强制取消已经共享给应用启动流程的数据任务。

当前允许缓存的页面包括：

- 日记记录；
- 事项查询；
- 统计工具；
- 调查工具；
- 脚本管理；
- Tracker 插件提供的 Redmine 管理页。

以下类别直接继承默认的 `false`：

- `WorkEditorViewModel` 等数量随业务数据增长的编辑器；
- 对话框、设置页和向导；
- Tracker 事项编辑区域、规则编辑器和管理页内部子页面；
- 主窗口、状态栏以及嵌套在其他页面中的辅助 ViewModel。

## 3. 实例与生命周期

主窗口内容区使用专用 `NavigationViewHost`。全局数据模板、Overlay 和其他 `ViewLocator` 仍默认不启用缓存，因此声明缓存资格只是必要条件，不会让 ViewModel 在任意宿主中自动驻留。

缓存以 `ViewModelBase` 实例作为键，并使用 `ConditionalWeakTable<ViewModelBase, Control>` 保存对应 View：

- 同一个 ViewModel 实例重复显示时返回同一个 View；
- 不同实例即使类型相同，也分别创建 View；
- ViewModel 不再被页面集合或其他业务对象引用后，缓存不会单独阻止该实例及其 View 被回收；
- View 创建时显式设置 `DataContext` 并调用 `SetView()`；
- 预热把 View 加入主导航宿主的真实视觉树，以透明、不可命中的状态完成模板、样式和布局，不提前调用 `OnShow()`；
- 页面真正成为当前页时调用 `OnShow()`，离开时调用 `OnHide()`，重复构建同一当前实例不会重复触发生命周期。

Avalonia 控件不能同时属于两个视觉父级。缓存 View 只属于主窗口的单一 `NavigationViewHost`；预热完成后和离开页面后仅设为不可见，不再执行 reparent。当前页位于更高 ZIndex 并恢复命中测试，非当前页不可见且不可命中。不可缓存页面离开时仍从宿主移除。`WorkEditorViewModel` 不进入这套主导航缓存；日记页内部只固定持有一个 `WorkEditorView`，选择变化时更换其 `DataContext`，不会为当天每个工作项常驻一棵完整编辑器视觉树。初始空日期使用的占位 ViewModel 只负责后台预实现该单一 View，首个真实事项接管后即释放。

## 4. 空闲预热

主窗口打开后延迟 750 ms，在 UI 线程后台优先级依次预热统计、脚本、查询、调查和 Tracker 动态管理页，每页之间间隔 75 ms。每个页面先以透明状态加入真实宿主，再在 Render 优先级使用内容区实际尺寸完成一次 `Measure/Arrange`，随后切换为不可见状态。这样可以预付 XAML 控件树创建、视觉父级挂载、模板/样式匹配和主要布局成本。

Tracker 配置发生变化并重建导航后，宿主会取消旧预热任务、移除不再属于页面集合的缓存 View，并针对新页面集合重新调度；宿主卸载时同样取消任务并结束当前页生命周期。

统计页进一步采用按需初始化：构造 `StatisticsViewModel` 时只创建轻量页签模型，不查询数据库，也不创建 LiveCharts 和 `TreeDataGrid`；页面真实显示后才在后台优先级初始化当前页签。切换统计页签时只加载被选中的页签，并以加载遮罩反馈异步刷新。首次显示仍包含当前页签图表和明细树创建成本，但不会再一次性支付所有统计页签成本。

脚本管理页覆盖 `PreloadAsync()`，复用应用启动阶段的脚本目录加载任务，并在后台把目录结果转换为列表模型。预加载阶段不修改隐藏页面的可观察集合，避免干扰首屏稳定；首次进入页面时先显示加载状态，再在 UI 后台优先级应用已经准备好的结果。执行历史和最多 2000 条会话日志只在对应页签第一次打开或数据变脏后生成，避免默认“脚本设置”页为不可见内容支付字符串格式化和列表绑定成本。日志分别记录脚本管理 View 初始化、目录等待、后台整理和 UI 应用耗时，用于区分 HDD I/O、脚本编译和界面绑定瓶颈。

## 5. 验证要求

- 单元测试验证同一实例复用、不同实例隔离、预热不提前触发生命周期，以及不可缓存实例不能预热；
- 单元测试验证预热 View 持续属于真实导航宿主、选择后复用同一实例，并正确执行 `OnShow`/`OnHide`；
- 单元测试验证导航宿主调用并等待页面 `PreloadAsync()`，且预加载未完成时切换到该页不会被后续隐藏；
- 单元测试验证 Tracker 动态页面加入后创建并预热 View，关闭 Tracker 后在页面回退时解除挂载，再次启用时为新的 ViewModel 创建新的 View；
- 单元测试验证统计页签在首次请求前不创建图表/明细树、不查询数据库，并且并发或重复初始化只执行一次；
- 单元测试验证缓存资格是默认关闭的虚契约，并明确保证 `WorkEditorViewModel` 不缓存；
- `ui-core-full` 验证主导航、查询、统计和日记编辑功能没有生命周期回归；
- CDP 树构建时向子节点传播祖先的不可见/禁用状态，避免常驻隐藏页面污染自动化定位；
- `ui-navigation-performance` 使用多进程轮换首次访问顺序，对比冷切换、热切换、CPU、工作集和进程 I/O；
- 性能结论至少基于 5 个新进程，冷切换 P95 的正式门禁建议使用 20 个以上新进程。
