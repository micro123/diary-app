# 主导航 View 实例缓存设计

## 1. 目标

主导航页面在首次打开后应复用已经创建的 Avalonia View，减少重复解析 XAML、创建控件树和建立绑定带来的热切换延迟。同时必须限制缓存范围，避免日记页中数量可能很大的事项编辑器、对话框和 Tracker 编辑区域长期驻留。

本设计采用“每个 ViewModel 实例对应至多一个可缓存 View 实例”，不按 ViewModel 类型共享 View。这样可以保留每个页面实例自己的绑定状态，也不会让同类型但不同业务实例错误共用视觉树。

## 2. 缓存资格契约

`ViewModelBase` 提供默认关闭的虚属性：

```csharp
public virtual bool IsViewCacheable => false;
```

View 缓存是显式加入能力。普通 ViewModel 无需覆盖该属性，默认不会进入缓存；只有生命周期稳定、实例数量受控的主导航页面才覆盖并返回 `true`。这样既保持安全默认值，也避免对话框、编辑器和第三方插件派生类被迫实现机械性的 `false`，并降低公共基类的兼容性成本。

当前允许缓存的页面包括：

- 日记记录；
- 事项查询；
- 统计工具；
- 调查工具；
- 脚本管理；
- Tracker 插件提供的 Redmine 管理页。

以下类别直接继承默认的 `false`：

- `WorkEditorViewModel` 等数量随业务数据增长的编辑器；
- 对话框、设置页和向导；
- Tracker 事项编辑区域、规则编辑器和管理页内部子页面；
- 主窗口、状态栏以及嵌套在其他页面中的辅助 ViewModel。

## 3. 实例与生命周期

主窗口内容区的 `ViewLocator` 显式启用 `CacheViews`。全局数据模板、Overlay 和其他 `ViewLocator` 默认不启用缓存，因此声明缓存资格只是必要条件，不会让 ViewModel 在任意宿主中自动驻留。

缓存以 `ViewModelBase` 实例作为键，并使用 `ConditionalWeakTable<ViewModelBase, Control>` 保存对应 View：

- 同一个 ViewModel 实例重复显示时返回同一个 View；
- 不同实例即使类型相同，也分别创建 View；
- ViewModel 不再被页面集合或其他业务对象引用后，缓存不会单独阻止该实例及其 View 被回收；
- View 创建时显式设置 `DataContext` 并调用 `SetView()`；
- 离屏预热只创建、测量和排列 View，不提前调用 `OnShow()`；
- 页面真正成为当前页时调用 `OnShow()`，离开时调用 `OnHide()`，重复构建同一当前实例不会重复触发生命周期。

Avalonia 控件不能同时属于两个视觉父级。缓存 View 只由主窗口单一内容宿主显示，页面切换时由 `ContentControl` 先移除旧内容，再挂载目标 View；不允许把同一缓存实例同时放入其他宿主。

## 4. 空闲预热

主窗口打开后延迟 750 ms，在 UI 线程后台优先级依次预热统计、脚本、查询、调查和 Tracker 动态管理页，每页之间间隔 75 ms。预热使用主窗口内容区的近似尺寸执行一次离屏 `Measure/Arrange`，降低首次显示前的控件树和基础布局成本。

Tracker 配置发生变化并重建导航后，会取消旧预热任务并针对新页面集合重新调度；主窗口清理时同样取消任务。预热异常只记录警告，不阻断导航。

预热不会把所有页面永久挂载在主视觉树中。首次挂载时仍可能发生样式、模板、真实父级布局和页面数据加载，因此统计页等复杂页面的首次切换不保证显著下降。若以后考虑常驻挂载，必须重新评估窗口缩放时所有页面同时布局、焦点导航、命中测试和内存增长，不应直接扩展当前缓存实现。

## 5. 验证要求

- 单元测试验证同一实例复用、不同实例隔离、预热不提前触发生命周期，以及不可缓存实例不能预热；
- 单元测试验证缓存资格是默认关闭的虚契约，并明确保证 `WorkEditorViewModel` 不缓存；
- `ui-core-full` 验证主导航、查询、统计和日记编辑功能没有生命周期回归；
- `ui-navigation-performance` 使用多进程轮换首次访问顺序，对比冷切换、热切换、CPU、工作集和进程 I/O；
- 性能结论至少基于 5 个新进程，冷切换 P95 的正式门禁建议使用 20 个以上新进程。
